# Стандартные профили: конфигурация GitHub (v1.8.4)

По умолчанию расширение читает:

`https://raw.githubusercontent.com/artemmalkin/Google-Region-Monitor/master/config/standard-profiles.json`

## Формат файла

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-23T00:00:00.000Z",
  "profiles": [
    {
      "id": "india",
      "name": "Индия",
      "profileGroup": "Южная Азия",
      "interfaceLang": "en",
      "resultLangs": "en, hi",
      "region": "IN",
      "queryGroups": [
        {
          "id": "industry",
          "name": "Отраслевые новости",
          "queries": ["site:.in (\"nuclear energy\" OR NPCIL OR SMR)"]
        },
        {
          "id": "company-projects",
          "name": "Проекты компании",
          "queries": ["site:.in (company OR project OR partnership) India"]
        }
      ],
      "queries": [
        "site:.in (\"nuclear energy\" OR NPCIL OR SMR)",
        "site:.in (company OR project OR partnership) India"
      ]
    }
  ]
}
```

### Обязательные и дополнительные поля

| Поле | Формат | Описание |
|---|---|---|
| `id` | Строка, 1–80 символов | Уникальный постоянный ID. Допустимы латинские буквы, цифры, `_`, `-`, `.` |
| `name` | Строка | Отображаемое название профиля |
| `profileGroup` | Строка, необязательно | Имя группы страновых профилей; одинаковая строка объединяет профили в один набор |
| `interfaceLang` | Строка | Код языка интерфейса Google для `hl` |
| `resultLangs` | Строка или массив строк | Языки фильтра `lr`, например `"id, en"` или `["id", "en"]` |
| `region` | Строка | Код страны для `gl`, например `ID`, `VN`, `BD` |
| `queryGroups` | Массив объектов, необязательно | Пользовательские группы запросов. У объекта — `id`, `name`, `queries` |
| `queryGroupsRevision` | Целое число, необязательно | Версия структуры групп; позволяет однократно мигрировать старый GitHub-кеш к новой структуре |
| `queries` | Массив строк | Плоский формат для совместимости со старыми версиями; при наличии `queryGroups` новой версии используется структура групп |

Пример объекта `queryGroups`:

```json
{
  "id": "social",
  "name": "Социальные сети",
  "queries": ["site:x.com country (topic OR project)"]
}
```

В `profiles` можно добавить до 500 записей. Все `id` должны быть уникальны.

В версии 1.6.0 тематически близкие термины сгруппированы через `OR`, чтобы не создавать несколько коротких Google-переходов на каждую вариацию. Разные тематические блоки и поиск по социальным платформам остаются отдельными, когда это улучшает точность источника. Запросы сокращены с учётом лимита Google в 32 слова.

## Встроенный каталог (добавлен в v1.6.0; поведение обновлено в v1.8.0)

В архив включён встроенный каталог из 19 профилей: Аргентина, Бангладеш, Боливия, Бразилия, Вьетнам, Индия, Индонезия, Китай, Куба, Малайзия, Мексика, Мьянма, Парагвай, Таиланд, Филиппины, Чили, Шри-Ланка, Южная Корея и Япония. Три прежние записи Вьетнам (`vietnam`), Индонезия (`indoneziya`) и Китай (`kitai`) сохранены; добавлены 16 новых.

Каталог из ZIP подхватывается непосредственно из `config/standard-profiles.json`. При совпадении `id` расширение объединяет встроенную запись и кеш GitHub. Если удалённая запись содержит непустой `queryGroups`, именно её группы и запросы считаются актуальными: удалённые группы не восстанавливаются из встроенного каталога. Для старого GitHub JSON, в котором есть только плоский `queries`, сохраняется совместимость: встроенные строки объединяются с уникальными дополнительными строками из GitHub. Профили, которых нет в удалённом кеше, добавляются из встроенного файла. Это делает новые профили доступными даже до обновления GitHub JSON. Скрытые встроенные ID хранятся локально в `hiddenBundledStandardProfileIds`. Обычные пользовательские профили хранятся отдельно и не затрагиваются.

Успешная синхронизация обновляет локальный кеш GitHub. При открытии боковой панели встроенный каталог объединяется с этим кешем. Переименование стандартного профиля и изменение его группы наборов (`profileGroup`) могут храниться локально через обычное сохранение; исходный стандартный ID остаётся прежним. Если меняются функциональные параметры профиля или его поисковые группы/строки, обычное сохранение создаёт отдельную пользовательскую копию. Для изменения опубликованной стандартной записи используйте кнопку «Сохранить изменения стандартного профиля в GitHub» и Fine-grained token с правом записи. Кнопка удаления рядом с выбором стандартного профиля удаляет исходную запись из GitHub после подтверждения.

Если в GitHub будет ошибка сети, HTTP 404 или JSON не пройдёт проверку, расширение оставит прежний кеш стандартных профилей.



## Группировка в интерфейсе (v1.8.0)

`profileGroup` позволяет объединять несколько стран в группу, например «Южная Азия» или «Латинская Америка». Название группы произвольное и не ограничено кодом расширения. В `queryGroups` указываются произвольно именуемые разделы запросов; пользователь может создавать, переименовывать и удалять их в редакторе профиля. Мониторинг отображает эти заголовки как есть.

Если профиль содержит только старое поле `queries`, расширение мигрирует его в нейтральную группу «Основные запросы». При синхронизации старого JSON без `queryGroups` встроенные поисковые строки объединяются с уникальными дополнительными строками GitHub. Если же задан непустой `queryGroups`, сгруппированная GitHub-запись является источником истины — её удалённые группы/запросы не восстанавливаются встроенным каталогом.

Переименование стандартного профиля и изменение `profileGroup` можно хранить локально. Чтобы сделать их общими, используйте «Сохранить изменения стандартного профиля в GitHub» с Fine-grained token.

## Изменение списка из расширения (v1.4.0)

При наличии Fine-grained token с правом `Contents: Read and write` расширение может добавить локальный профиль, обновить выбранный стандартный профиль по его `id` или удалить стандартный профиль. Каждая операция меняет `config/standard-profiles.json` через GitHub Contents API и создаёт commit. После записи список повторно загружается в расширение. Удаление стандартной записи влияет на всех пользователей этого стандартного набора при их следующей синхронизации.


## Совместимость Preferences (v1.4.1)

Чтение и изменение настроек Google Preferences выполняется по структурным атрибутам (`data-pid`, `data-value`, `data-alllangmap`, `aria-selected`, `aria-checked`) и не зависит от локализованных подписей интерфейса.


## Разделение начальных поисковых групп в v1.8.2

В стандартном каталоге начальные запросы распределены по двум группам: «Основные запросы» и «Росатом и его проекты». Это обычные данные `queryGroups`, не зарезервированные категории. Пользователь может менять название, содержимое, переносить запросы и удалять группы через редактор профиля. Код расширения не распознаёт Rosatom/Росатом и не классифицирует запросы автоматически.

В профилях `vietnam`, `indoneziya` и `kitai` сохранены точные поисковые строки Rosatom из исходного каталога v1.5.4.

`queryGroupsRevision: 2` помечает текущую структуру. При первом обновлении устаревшего GitHub-профиля новые группы берутся из встроенного каталога, а пользовательские дополнительные группы и строки сохраняются. После публикации профиля с ревизией 2 GitHub-версия становится авторитетной для групп/запросов.
