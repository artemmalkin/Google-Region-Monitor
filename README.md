# Google Region Monitor — Chrome extension v1.2.0

Расширение Manifest V3 с боковой панелью Chrome, синхронизацией стандартных профилей из GitHub и локальными пользовательскими профилями.

## Установка

1. Распакуйте архив в отдельную папку.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное** и выберите эту папку.
5. Закрепите значок расширения на панели Chrome, чтобы быстро открывать боковую панель.

## Модель профилей

Расширение разделяет профили на два типа:

- **Стандартные · GitHub** — поступают из файла конфигурации в публичном GitHub-репозитории. При синхронизации этот список заменяется актуальным содержимым файла.
- **Мои профили · локально** — хранятся в `chrome.storage.local` на этом устройстве. Они не удаляются и не перезаписываются при обновлении стандартного списка.

Если пользователь выбирает стандартный профиль и меняет хотя бы одно поле, расширение создаёт отдельную пользовательскую копию. Стандартный профиль остаётся неизменным. Копия содержит `sourceStandardId` и `sourceStandardName` для понимания происхождения.

### Конфигурация стандартных профилей

По умолчанию используется `config/standard-profiles.json` в ветке `main`.

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-19T00:00:00.000Z",
  "profiles": [
    {
      "id": "vietnam",
      "name": "Вьетнам",
      "interfaceLang": "vi",
      "resultLangs": "vi, en",
      "region": "VN",
      "queries": ["rosatom", "\"rosatom\" AND \"rooppur\""]
    }
  ]
}
```

Поля:

| Поле | Значение |
|---|---|
| `id` | Уникальный постоянный ID профиля: латиница, цифры, `.`, `_`, `-` |
| `name` | Название, отображаемое в расширении |
| `interfaceLang` | Язык Google (`hl`), например `vi`, `en`, `id` |
| `resultLangs` | Фильтр языков (`lr`), строка через запятую или массив, например `"vi, en"` |
| `region` | Страна поиска (`gl`), например `VN`, `ID`, `BD` |
| `queries` | Массив поисковых запросов, каждый запрос отдельной строкой |

В интерфейсе можно изменить репозиторий `owner/repository`, ветку и путь к JSON-файлу.

## Синхронизация стандартных профилей

- Кнопка **Обновить стандартные профили** немедленно загружает конфигурацию из GitHub.
- Автоматическая синхронизация выполняется через `chrome.alarms` примерно раз в 24 часа, даже если боковая панель закрыта (при условии, что Chrome запущен и расширение не отключено). Сигнал будильника не будит выключенный/спящий компьютер; после пробуждения Chrome обработает пропущенный сигнал. Точное время может сдвигаться из-за планировщика браузера.
- При запуске Chrome проверяется, не устарела ли локальная копия. Если с момента последней успешной синхронизации прошло менее 24 часов и источник тот же, лишний запрос не выполняется.
- При временной ошибке предыдущие стандартные профили сохраняются; пользовательские профили не затрагиваются.

Для работы автоматической загрузки репозиторий и JSON должны быть доступны по адресу `raw.githubusercontent.com`. Для приватного репозитория этот вариант требует отдельной авторизации и в текущей версии не используется.

## Пользовательские профили: импорт и экспорт

- **Экспорт профиля** выгружает только выбранный пользовательский профиль в отдельный JSON-файл.
- **Импорт из файла** принимает такой JSON, создаёт новую локальную копию с новым ID и не перезаписывает существующий профиль.
- Пользовательские профили хранятся отдельно от GitHub-стандартов.

## Публикация пользовательского профиля в стандартные

Выберите/отредактируйте пользовательский профиль и нажмите **Добавить мой профиль в GitHub**.

Есть два режима:

1. **Без токена:** расширение синхронизирует текущий список, формирует и скачивает обновлённый `standard-profiles.json`. Загрузите его в репозиторий по указанному пути через GitHub.
2. **С Fine-grained Personal Access Token:** расширение может напрямую создать commit через GitHub Contents API. Токену требуется доступ только к нужному репозиторию и разрешение `Contents: Read and write`. Токен хранится в локальном хранилище расширения Chrome; он не записывается в экспортируемые JSON-файлы и не отправляется на другие сервисы. Удалить его можно, очистив поле токена и сохранив настройки.

Рекомендуется ограничить токен одним репозиторием. Не публикуйте его в GitHub и не передавайте другим пользователям.

## Обновления самого расширения

В репозитории добавлен workflow `.github/workflows/release.yml`. Чтобы опубликовать новую версию:

1. Увеличьте `version` в `manifest.json`.
2. Отправьте изменения в GitHub.
3. Создайте тег, совпадающий с версией, например `v1.2.0`.
4. GitHub Actions соберёт `google-region-monitor.zip` и прикрепит его к Release.
5. Расширение сможет проверить Release и предложить скачать обновление.

Для уже установленного распакованного расширения Chrome требует ручной перезагрузки после получения обновлённой папки. GitHub-синхронизация стандартных профилей автоматическая; замена собственных файлов распакованного расширения самим расширением — отдельная задача распространения, обычно решаемая Chrome Web Store.

## Google Preferences и поиск

- `data-pid="hl"` — язык интерфейса.
- `data-pid="lr"` — языковой фильтр результатов.
- `data-pid="gl"` — регион поиска.
- В поисковой выдаче поддерживаются контейнеры `#rso .MjjYud`, сниппеты `.VwiC3b`/`.yXK7lf` и пагинация `a#pnnext` (с альтернативными селекторами).
- Поисковые URL получают параметры `hl`, `lr`, `gl` и `tbs=qdr:*`.
- Google CAPTCHA, согласия и иные защитные ограничения не обходятся.

В присланном HTML выдачи используется индонезийский интерфейс (`lang="id"`), контейнеры результатов `.MjjYud`, блок `#rso`, сниппеты `.VwiC3b` и ссылка пагинации `#pnnext`. Эти селекторы теперь стоят первыми в алгоритме сбора.

## Версия 1.3.0 — настройки GitHub в файле конфигурации

Параметры репозитория больше не отображаются в интерфейсе. Перед сборкой откройте `github-config.js` и задайте `owner`, `repository`, `branch`, `standardProfilesPath`. Fine-grained token не помещайте в этот файл: он вводится в расширении и хранится в `chrome.storage.local`. Кнопка публикации отображается только при непустом токене. Кнопка «Проверить обновление» одновременно принудительно синхронизирует стандартные профили и проверяет GitHub Release.
