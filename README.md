# Google Region Monitor — Chrome extension v1.4.5

Расширение Manifest V3 с боковой панелью Chrome, синхронизацией стандартных профилей из GitHub и локальными пользовательскими профилями.

В версии 1.4.5 исправлены переключение фокуса вкладок, применение Preferences перед мониторингом и привязка списка чекбоксов к конкретному профилю. Поиск по-прежнему использует параметр `filter=0`: Google просится включать результаты, которые обычно скрывает как очень похожие на уже показанные. Расширение повторно добавляет этот параметр к каждой ссылке пагинации. Для полноты мониторинга продолжает обходить страницы последовательно; отключение фильтрации не гарантирует наличие в выдаче каждой страницы из индекса Google. Параметр `num=100` намеренно не используется, поскольку Google объявлял его неподдерживаемым и его работа нестабильна.

## Установка

1. Распакуйте архив в отдельную папку.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное** и выберите эту папку.
5. Закрепите значок расширения на панели Chrome, чтобы быстро открывать боковую панель.

## Применение настроек Google и возврат к русскому профилю

При выборе профиля расширение находит вкладку Google Preferences (или открывает её) и активирует окно Chrome и саму вкладку перед изменением настроек. Вкладка остаётся открытой на переднем плане — изменения не отправляются в скрытой фоновой вкладке. Кнопка «Применить профиль в Google» использует тот же сценарий.

Для обычной работы добавлена команда «Вернуть русский профиль для обычной работы»: она устанавливает `hl=ru`, `lr=lang_ru`, `gl=RU`. В разделе «Мониторинг» эта команда также доступна отдельно. По умолчанию после завершения мониторинга русский профиль восстанавливается автоматически; флажок позволяет отключить автоматический возврат. Восстановление не меняет выбранный профиль мониторинга и его локальные данные.

## Модель профилей

Расширение разделяет профили на два типа:

- **Стандартные · GitHub** — поступают из файла конфигурации в публичном GitHub-репозитории. При синхронизации этот список заменяется актуальным содержимым файла.
- **Мои профили · локально** — хранятся в `chrome.storage.local` на этом устройстве. Они не удаляются и не перезаписываются при обновлении стандартного списка.

Если пользователь выбирает стандартный профиль и нажимает обычную кнопку «Сохранить профиль», расширение создаёт отдельную пользовательскую копию. Стандартный профиль остаётся неизменным. Копия содержит `sourceStandardId` и `sourceStandardName` для понимания происхождения.

При заполненном Fine-grained token доступны отдельные действия над оригиналом: **«Сохранить изменения стандартного профиля в GitHub»** обновляет запись с тем же `id`, а кнопка удаления рядом с выбором профиля удаляет запись из GitHub после дополнительного подтверждения. Эти действия создают commit в целевой ветке, затем расширение принудительно обновляет локальный список. Они влияют на стандартный список для всех пользователей репозитория.

### Конфигурация стандартных профилей

Используется `config/standard-profiles.json` в репозитории `artemmalkin/Google-Region-Monitor`, ветка `master`. Эти значения заданы в `github-config.js`.

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-19T00:00:00.000Z",
  "profiles": [
    {
      "id": "vietnam",
      "name": "Вьетнам",
      "interfaceLang": "vi",
      "resultLangs": "vi, en",
      "region": "VN",
      "queries": ["rosatom", "\"rosatom\" AND \"rooppur\""]
    }
  ]
}
```

Поля:

| Поле | Значение |
|---|---|
| `id` | Уникальный постоянный ID профиля: латиница, цифры, `.`, `_`, `-` |
| `name` | Название, отображаемое в расширении |
| `interfaceLang` | Язык Google (`hl`), например `vi`, `en`, `id` |
| `resultLangs` | Фильтр языков (`lr`), строка через запятую или массив, например `"vi, en"` |
| `region` | Страна поиска (`gl`), например `VN`, `ID`, `BD` |
| `queries` | Массив поисковых запросов, каждый запрос отдельной строкой |

Репозиторий `owner/repository`, ветка и путь к JSON-файлу задаются в `github-config.js`.

## Синхронизация стандартных профилей

- Кнопка **Проверить обновление** проверяет GitHub Release и одновременно принудительно загружает стандартные профили из GitHub.
- Автоматическая синхронизация выполняется через `chrome.alarms` примерно раз в 24 часа, даже если боковая панель закрыта (при условии, что Chrome запущен и расширение не отключено). Сигнал будильника не будит выключенный/спящий компьютер; после пробуждения Chrome обработает пропущенный сигнал. Точное время может сдвигаться из-за планировщика браузера.
- При запуске Chrome проверяется, не устарела ли локальная копия. Если с момента последней успешной синхронизации прошло менее 24 часов и источник тот же, лишний запрос не выполняется.
- При временной ошибке предыдущие стандартные профили сохраняются; пользовательские профили не затрагиваются.

Для работы автоматической загрузки репозиторий и JSON должны быть доступны по адресу `raw.githubusercontent.com`. Для приватного репозитория этот вариант требует отдельной авторизации и в текущей версии не используется.

## Пользовательские профили: импорт и экспорт

- **Экспорт профиля** выгружает только выбранный пользовательский профиль в отдельный JSON-файл.
- **Импорт из файла** принимает такой JSON, создаёт новую локальную копию с новым ID и не перезаписывает существующий профиль.
- Пользовательские профили хранятся отдельно от GitHub-стандартов.

## Публикация и управление стандартными профилями в GitHub

Вставьте Fine-grained Personal Access Token в поле GitHub Fine-grained token. Требуется доступ только к целевому репозиторию и разрешение `Contents: Read and write`.

- **Добавить мой профиль в GitHub** — добавляет выбранный локальный пользовательский профиль в массив `profiles`.
- **Сохранить изменения стандартного профиля в GitHub** — обновляет выбранный стандартный профиль по его постоянному `id`; остальные профили и дополнительные поля JSON сохраняются.
- **Кнопка × рядом с выбором профиля** — удаляет выбранный стандартный профиль из GitHub. Перед удалением показывается подтверждение. Для локального пользовательского профиля эта же кнопка выполняет локальное удаление.

После каждого успешного commit расширение принудительно синхронизирует стандартный список. GitHub Contents API использует SHA текущего файла; при конфликте одновременных изменений расширение сообщает об ошибке и предлагает обновить список перед повтором.

Токен хранится в локальном хранилище расширения Chrome; он не записывается в `github-config.js`, экспорт профиля или JSON конфигурации. Рекомендуется ограничить токен одним репозиторием. Не публикуйте его и не передавайте другим пользователям.

## Обновления самого расширения

В репозитории добавлен workflow `.github/workflows/release.yml`. Чтобы опубликовать новую версию:

1. Увеличьте `version` в `manifest.json`.
2. Отправьте изменения в GitHub.
3. Создайте тег, совпадающий с версией, например `v1.4.1`.
4. GitHub Actions соберёт `google-region-monitor.zip` и прикрепит его к Release.
5. Расширение сможет проверить Release и предложить скачать обновление.

Для уже установленного распакованного расширения Chrome требует ручной перезагрузки после получения обновлённой папки. GitHub-синхронизация стандартных профилей автоматическая; замена собственных файлов распакованного расширения самим расширением — отдельная задача распространения, обычно решаемая Chrome Web Store.

## Мониторинг выбранных запросов и остановка (v1.4.3)

В разделе «Мониторинг» отметьте только запросы, которые нужно включить в отчёт. Кнопка «Сформировать отчёт» использует непосредственно состояние этих флажков: список больше не перестраивается перед запуском и не сбрасывает выбор.

Во время сбора доступна кнопка «Остановить». Она прерывает ожидание текущей незавершённой страницы, не добавляет её в отчёт и формирует HTML-отчёт по уже собранным страницам. В шапке отчёта указывается, был ли мониторинг завершён полностью или остановлен пользователем. При включённой опции автоматического восстановления после остановки также применяется русский профиль Google.

## Google Preferences и поиск

- `data-pid="hl"` — язык интерфейса.
- `data-pid="lr"` — языковой фильтр результатов.
- `data-pid="gl"` — регион поиска.
- В поисковой выдаче поддерживаются контейнеры `#rso .MjjYud`, сниппеты `.VwiC3b`/`.yXK7lf` и пагинация `a#pnnext` (с альтернативными селекторами).
- Поисковые URL получают параметры `hl`, `lr`, `gl` и `tbs=qdr:*`.
- Google CAPTCHA, согласия и иные защитные ограничения не обходятся.

В присланном HTML выдачи используется индонезийский интерфейс (`lang="id"`), контейнеры результатов `.MjjYud`, блок `#rso`, сниппеты `.VwiC3b` и ссылка пагинации `#pnnext`. Эти селекторы теперь стоят первыми в алгоритме сбора.

## Версия 1.4.5 — фокус вкладок и профиль мониторинга

Все вкладки, которые активирует или открывает расширение (Google Preferences и поисковая вкладка), переводятся на передний план; фокус повторно устанавливается после загрузки и перед чтением результатов. Перед началом мониторинга берётся точный профиль из списка «Профиль региона» в разделе «Мониторинг», его настройки применяются в Google Preferences и проверяются. Если Google не подтвердил настройки, поиск не начинается. Профиль и отмеченные запросы фиксируются для всего запуска. Список запросов помечает ключ профиля, для которого он отрисован; при быстрой смене профиля нельзя запустить отчёт с чекбоксами от предыдущего профиля. Во время подготовки и мониторинга выбор профиля и запросов заблокирован.

## Версия 1.3.0 — настройки GitHub в файле конфигурации

Параметры репозитория больше не отображаются в интерфейсе. Перед сборкой откройте `github-config.js` и задайте `owner`, `repository`, `branch`, `standardProfilesPath`. Fine-grained token не помещайте в этот файл: он вводится в расширении и хранится в `chrome.storage.local`. Кнопка публикации отображается только при непустом токене. Кнопка «Проверить обновление» одновременно принудительно синхронизирует стандартные профили и проверяет GitHub Release.


## Версия 1.4.0 — редактирование и удаление стандартных профилей

Для стандартных профилей добавлены прямое обновление записи и удаление из GitHub с подтверждением. Обе операции создают commit через GitHub Contents API, используют SHA файла для защиты от перезаписи чужого commit и после изменения запускают принудительную синхронизацию. Обычная кнопка «Сохранить профиль» по-прежнему создаёт локальную копию стандарта.


## Версия 1.4.1 — совместимость с языком Google Preferences

Распознавание настроек и применение профиля больше не зависят от языка надписей Google. Используются постоянные атрибуты `data-pid`, `data-value`, `data-alllangmap`, ARIA-состояния элементов и служебный `jsaction` подтверждения. Для открытия меню нажимается внутренняя область `.HrqWPb`, а не внешний контейнер настроек. Сначала применяются языки результатов и регион; язык интерфейса (`hl`) применяется последним, поскольку Google может перерисовать страницу после его изменения.
