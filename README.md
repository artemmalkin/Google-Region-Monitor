# Google Region Monitor — Chrome extension v1.8.0

Расширение Manifest V3 для мониторинга Google Search по страновым профилям. В каталоге 19 стандартных профилей из методичек по Латинской Америке, Южной Азии, Восточной и Юго-Восточной Азии. Профили можно объединять в произвольные группы (например, «Южная Азия»), а поисковые выражения внутри каждого профиля — в пользовательские группы с любыми названиями. Ни названия, ни тематика групп не зашиты в код. Также доступны локальные пользовательские профили, синхронизация стандартных профилей из GitHub, минимальный глобальный интервал между переходами Google, последовательная пагинация, экспорт HTML-отчёта и опциональная фильтрация региональной принадлежности СМИ через веб-версию ChatGPT.

Поиск использует параметр `filter=0`, чтобы Google включал результаты, которые обычно скрывает как очень похожие на уже показанные. Этот параметр повторно добавляется к ссылкам пагинации. Страницы обходятся последовательно и с общей пользовательской задержкой; `num=100` не используется. Google CAPTCHA и другие защитные ограничения не обходятся.

## Установка

1. Распакуйте архив в отдельную папку.
2. Откройте `chrome://extensions`.
3. Включите **Режим разработчика**.
4. Нажмите **Загрузить распакованное** и выберите эту папку.
5. Закрепите значок расширения на панели Chrome, чтобы быстро открывать боковую панель.

## Применение настроек Google и возврат к русскому профилю

При выборе профиля расширение находит вкладку Google Preferences (или открывает её) и активирует окно Chrome и саму вкладку перед изменением настроек. Вкладка остаётся открытой на переднем плане — изменения не отправляются в скрытой фоновой вкладке. Кнопка «Применить профиль в Google» использует тот же сценарий.

Для обычной работы доступна команда «Вернуть русский профиль для обычной работы»: она устанавливает `hl=ru`, `lr=lang_ru`, `gl=RU`. В разделе «Мониторинг» эта команда также доступна отдельно. По умолчанию после завершения мониторинга русский профиль восстанавливается автоматически; флажок позволяет отключить автоматический возврат. Восстановление не меняет выбранный профиль мониторинга и его локальные данные.

## Группы профилей и группировка списка

В каждом профиле есть поле **«Группа профилей»**. Чтобы собрать несколько стран в один набор, укажите у них одно и то же название, например «Южная Азия», «Латинская Америка» или своё. Название можно выбрать из подсказок или ввести новое. Группы создаются автоматически по значениям этого поля; отдельный фиксированный список регионов в коде не используется.

Оба выпадающих списка профилей — в разделе «Профили» и в разделе «Мониторинг» — строятся по `profileGroup`. Названия групп сортируются по русскому алфавиту, профили внутри группы также сортируются по алфавиту. Профили без значения `profileGroup` помещаются в «Без группы». Порядок элементов в JSON не определяет порядок интерфейса.

## Произвольные группы поисковых запросов

В редакторе профиля можно добавлять и удалять группы запросов, менять их названия и состав. Каждая строка внутри группы — отдельный запрос Google. Расширение отображает названия этих групп над соответствующими чекбоксами в «Мониторинге». Например, можно самостоятельно создать группы «Новости отрасли», «Проекты компании», «Социальные сети», «Литий» — это примеры пользовательских названий, а не встроенные категории.

Классификации запросов по ключевым словам компании или заранее заданным темам в коде нет. Перемещение запроса в группу выполняется через редактор профиля. При запуске мониторинга отмеченные запросы собираются из всех выбранных групп; на запуск не влияют названия групп.

## Модель профилей

Расширение объединяет три источника профилей:

- **Стандартные · GitHub** — загружаются из файла конфигурации в GitHub-репозитории.
- **Встроенный каталог** — профили из `config/standard-profiles.json` внутри архива. Он дополняет каталог, если удалённый JSON ещё не содержит часть стандартных профилей.
- **Мои профили · локально** — пользовательские записи в `chrome.storage.local`; синхронизация GitHub их не удаляет и не перезаписывает.

Переименование стандартного профиля и изменение его `profileGroup` сохраняются как локальное переопределение без создания копии и не меняют общий каталог. Если изменить язык, регион или группы поисковых запросов стандартного профиля, обычная кнопка «Сохранить профиль» создаёт локальную пользовательскую копию, оставляя стандартную запись нетронутой. При наличии Fine-grained token можно отправить изменённые значения стандартного профиля в GitHub кнопкой **«Сохранить изменения стандартного профиля в GitHub»**. Для переименования в общем каталоге используйте её после изменения названия.

Стандартный профиль можно скрыть локально (если он только во встроенном каталоге) или удалить из GitHub (если он опубликован там). Пользовательские профили удаляются только локально.

## Конфигурация стандартных профилей

Используется `config/standard-profiles.json` в репозитории `artemmalkin/Google-Region-Monitor`, ветка `master`. Эти значения заданы в `github-config.js`.

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-23T00:00:00.000Z",
  "profiles": [
    {
      "id": "india",
      "name": "Индия",
      "profileGroup": "Южная Азия",
      "interfaceLang": "en",
      "resultLangs": "en, hi",
      "region": "IN",
      "queryGroups": [
        {
          "id": "industry",
          "name": "Атомная энергетика и промышленность",
          "queries": [
            "site:.in (\"nuclear energy\" OR \"nuclear power plant\" OR NPCIL OR SMR)"
          ]
        },
        {
          "id": "social",
          "name": "Социальные сети",
          "queries": [
            "(site:x.com OR site:facebook.com OR site:instagram.com) India (nuclear OR NPCIL)"
          ]
        }
      ],
      "queries": [
        "site:.in (\"nuclear energy\" OR \"nuclear power plant\" OR NPCIL OR SMR)",
        "(site:x.com OR site:facebook.com OR site:instagram.com) India (nuclear OR NPCIL)"
      ]
    }
  ]
}
```

Поля профиля:

| Поле | Значение |
|---|---|
| `id` | Уникальный постоянный ID профиля: латиница, цифры, `.`, `_`, `-` |
| `name` | Название профиля, отображаемое в расширении |
| `profileGroup` | Необязательное имя группы страновых профилей; одинаковое значение объединяет профили в одну группу |
| `interfaceLang` | Язык Google (`hl`), например `vi`, `en`, `id` |
| `resultLangs` | Фильтр языков (`lr`), строка через запятую или массив, например `"vi, en"` |
| `region` | Страна поиска (`gl`), например `VN`, `ID`, `BD` |
| `queryGroups` | Необязательный массив произвольно именуемых групп; каждая группа содержит `id`, `name` и массив `queries` |
| `queries` | Совместимый со старыми версиями плоский массив поисковых строк. В новой версии при наличии непустого `queryGroups` используется сгруппированная структура; `queries` сохраняется для старых клиентов и миграции. |

Пример одной группы:

```json
{
  "id": "company-projects",
  "name": "Проекты и партнёрства",
  "queries": ["company OR project OR local-project"]
}
```

`queryGroups` в синхронизируемом GitHub JSON — источник истины, если массив групп задан. Поэтому переименование/удаление группы или запроса в таком профиле не будет отменено встроенным каталогом при следующей синхронизации. Старые JSON, содержащие только `queries`, продолжают поддерживаться: их строки отображаются внутри одной группы «Основные запросы»; уникальные дополнительные старые строки сохраняются в группе «Дополнительные запросы».

## Синхронизация стандартных профилей

- Кнопка **Проверить обновление** проверяет GitHub Release и одновременно принудительно загружает стандартные профили из GitHub.
- Автоматическая синхронизация выполняется через `chrome.alarms` примерно раз в 24 часа, пока Chrome запущен.
- При запуске Chrome проверяется возраст локального кеша; если он актуален и источник тот же, лишняя загрузка не выполняется.
- При временной ошибке предыдущие стандартные профили сохраняются; встроенный каталог дополняет отсутствующие записи; пользовательские профили не затрагиваются.

Для работы автоматической загрузки репозиторий и JSON должны быть доступны по адресу `raw.githubusercontent.com`.

## Пользовательские профили: импорт и экспорт

- **Экспорт профиля** выгружает выбранный пользовательский профиль, включая группы профилей и поисковых запросов.
- **Импорт из файла** принимает JSON, создаёт новую локальную копию с новым ID и не перезаписывает существующий профиль.
- Плоские старые профили автоматически мигрируют при открытии редактора в одну группу «Основные запросы»; исходные строки поиска сохраняются.

## Публикация и управление стандартными профилями в GitHub

Вставьте Fine-grained Personal Access Token в поле GitHub Fine-grained token. Требуется доступ только к целевому репозиторию и разрешение `Contents: Read and write`.

- **Добавить мой профиль в GitHub** — публикует выбранный локальный пользовательский профиль, включая `profileGroup` и `queryGroups`.
- **Сохранить изменения стандартного профиля в GitHub** — обновляет выбранный профиль по постоянному `id`, включая его название, группу профилей и группы запросов.
- **Кнопка × рядом с выбором профиля** — скрывает встроенный профиль локально или удаляет запись из GitHub после подтверждения.

Локальные переименования стандартного профиля не перезаписывают GitHub JSON автоматически. Чтобы поделиться переименованием/группой со всеми пользователями каталога, подтвердите сохранение в GitHub.

Токен хранится в локальном хранилище расширения Chrome; он не записывается в `github-config.js`, экспорт профиля или JSON конфигурации.

## Обновления самого расширения

В репозитории добавлен workflow `.github/workflows/release.yml`. Чтобы опубликовать новую версию:

1. Увеличьте `version` в `manifest.json`.
2. Отправьте изменения в GitHub.
3. Создайте тег, совпадающий с версией, например `v1.8.0`.
4. GitHub Actions соберёт `google-region-monitor.zip` и прикрепит его к Release.
5. Расширение сможет проверить Release и предложить скачать обновление.

Для уже установленного распакованного расширения Chrome требует ручной перезагрузки после получения обновлённой папки.


## Мониторинг выбранных запросов и остановка (v1.4.3)

В разделе «Мониторинг» отметьте только запросы, которые нужно включить в отчёт. Кнопка «Сформировать отчёт» использует непосредственно состояние этих флажков: список больше не перестраивается перед запуском и не сбрасывает выбор.

Во время сбора доступна кнопка «Остановить». Она прерывает ожидание текущей незавершённой страницы, не добавляет её в отчёт и формирует HTML-отчёт по уже собранным страницам. В шапке отчёта указывается, был ли мониторинг завершён полностью или остановлен пользователем. При включённой опции автоматического восстановления после остановки также применяется русский профиль Google.

## Google Preferences и поиск

В версии 1.5.4 добавлен общий минимальный интервал между поисковыми запросами Google (0–600 секунд, по умолчанию 2 секунды). Ограничитель находится в background service worker и сериализует выдачу слотов между окнами расширения; интервал применяется к первому открытию страницы поиска, всем переходам пагинации и новым запросам в очереди. Время последнего поискового перехода сохраняется в локальном хранилище. Значение 0 отключает задержку. Если Google явно показывает CAPTCHA или ограничение, оставшиеся запросы запуска не отправляются.

- `data-pid="hl"` — язык интерфейса.
- `data-pid="lr"` — языковой фильтр результатов.
- `data-pid="gl"` — регион поиска.
- В поисковой выдаче поддерживаются контейнеры `#rso .MjjYud`, сниппеты `.VwiC3b`/`.yXK7lf` и пагинация `a#pnnext` (с альтернативными селекторами).
- Поисковые URL получают параметры `hl`, `lr`, `gl` и `tbs=qdr:*`.
- Google CAPTCHA, согласия и иные защитные ограничения не обходятся.

В присланном HTML выдачи используется индонезийский интерфейс (`lang="id"`), контейнеры результатов `.MjjYud`, блок `#rso`, сниппеты `.VwiC3b` и ссылка пагинации `#pnnext`. Эти селекторы теперь стоят первыми в алгоритме сбора.

## Версия 1.4.7 — опциональная проверка и восстановление рабочего обмена ChatGPT

- Добавлен переключатель «Проверять региональную принадлежность СМИ через ChatGPT» в настройках мониторинга. Состояние сохраняется локально; по умолчанию опция включена.
- При отключении проверка не запускается, а все найденные ссылки попадают в отчёт без изменений.
- Файл `chatgpt_content.js` скопирован из расширения-примера без изменений. Отправка/получение ответа использует исходный протокол `chatgpt_request`, `chatgpt_response_ready` и `chatgpt_error_ready`.
- Функция `startNewChatGPTChat()` перенесена из расширения-примера без изменений; для каждого пакета ссылок открывается новый чат.
- Удалён самописный выбор режима размышления, который мог нажимать элементы интерфейса не по назначению. Пример не содержит отдельного кода выбора reasoning-режима ChatGPT.

## Версия 1.4.6 — фильтр региональных СМИ через ChatGPT

В версии 1.4.6 впервые добавлен AI-фильтр региональности: расширение собирает уникальные ссылки из Google-результатов и передаёт их в веб-версию ChatGPT пакетами. В версии 1.4.7 интеграция обмена заменена на рабочую реализацию из приложенного расширения-примера: `chatgpt_content.js` и `startNewChatGPTChat()` перенесены без изменений; каждый пакет отправляется в отдельном новом чате через протокол `chatgpt_request` / `chatgpt_response_ready`.

Проверка включается и выключается чекбоксом в разделе «Мониторинг»; настройка сохраняется локально. При включённой проверке ChatGPT получает домен, URL, заголовок, сниппет и поисковый запрос, а затем возвращает JSON со списком исключаемых ID. Расширение принимает только ID из текущего пакета и удаляет соответствующие ссылки со всех страниц отчёта, включая повторы. При выключенной проверке или ошибке ChatGPT все найденные ссылки остаются в отчёте.

Рабочий код из примера не переключает reasoning/model mode ChatGPT — он отвечает только за открытие нового чата, отправку сообщения и получение ответа. Поэтому расширение больше не пытается нажимать самописные кнопки выбора режима, которые могли задевать посторонние элементы интерфейса. Для работы требуется активная авторизация в `https://chatgpt.com/`.

## Версия 1.4.5 — фокус вкладок и профиль мониторинга

Все вкладки, которые активирует или открывает расширение (Google Preferences и поисковая вкладка), переводятся на передний план; фокус повторно устанавливается после загрузки и перед чтением результатов. Перед началом мониторинга берётся точный профиль из списка «Профиль региона» в разделе «Мониторинг», его настройки применяются в Google Preferences и проверяются. Если Google не подтвердил настройки, поиск не начинается. Профиль и отмеченные запросы фиксируются для всего запуска. Список запросов помечает ключ профиля, для которого он отрисован; при быстрой смене профиля нельзя запустить отчёт с чекбоксами от предыдущего профиля. Во время подготовки и мониторинга выбор профиля и запросов заблокирован.

## Версия 1.4.1 — совместимость с языком Google Preferences

Распознавание настроек и применение профиля больше не зависят от языка надписей Google. Используются постоянные атрибуты `data-pid`, `data-value`, `data-alllangmap`, ARIA-состояния элементов и служебный `jsaction` подтверждения. Для открытия меню нажимается внутренняя область `.HrqWPb`, а не внешний контейнер настроек. Сначала применяются языки результатов и регион; язык интерфейса (`hl`) применяется последним, поскольку Google может перерисовать страницу после его изменения.


## Версия 1.8.0 — пользовательские группы профилей и поисковых запросов

- Добавлено поле `profileGroup`: присвойте одинаковое название нескольким странам, чтобы объединить их в один набор/регион в обоих выпадающих списках профилей. Группы не ограничены фиксированным перечнем.
- Добавлен формат `queryGroups`: внутри профиля можно создавать, переименовывать и удалять группы запросов, а также переносить строки между ними. Заголовки групп в «Мониторинге» берутся из данных профиля.
- Удалена жёстко заданная классификация групп по ключевым словам Rosatom/Росатом. Код мониторинга не привязан к конкретной компании или теме.
- Переименование стандартного профиля и изменение его группы сохраняются локально без создания копии. При наличии GitHub token эти изменения можно опубликовать в общий JSON. Изменение языков, региона и поисковых групп обычной кнопкой создаёт локальную копию.
- Для обратной совместимости старые профили с массивом `queries` мигрируют в одну нейтральную группу «Основные запросы». JSON со сгруппированным `queryGroups` становится источником истины при синхронизации; удалённые пользователем группы и строки не восстанавливаются из встроенного каталога.
- README, `STANDARD_PROFILES.md`, JSON Schema и GitHub-инструкции обновлены под новый формат.

В версии 1.7.0 применялась специальная классификация поисковых строк по упоминаниям Rosatom/Росатом. ## Версия 1.6.0 — страновые профили по методичкам и компактные поисковые запросы

Каталог расширен до 19 страновых профилей по двум методическим документам: Латинская Америка, Южная Азия, Восточная и Юго-Восточная Азия. Три существовавших стандартных профиля (Вьетнам, Индонезия, Китай) сохранены с теми же ID, языковыми настройками и кодами региона; их поисковые темы дополнены формулировками методичек. Добавлены ещё 16 стран.

Поисковые строки сокращены до наиболее различающих терминов и сгруппированы по `OR`: близкие ключевые слова одной темы объединены, действительно разные тематические блоки оставлены отдельными запросами. Для ряда стран запросы по СМИ и соцсетям остаются отдельными, чтобы не смешивать источники. Большинство профилей содержит 1–2 запроса; для Индии, Индонезии, Малайзии, Шри-Ланки, Таиланда и Южной Кореи — до 3 тематических запросов. Длинные перечни синонимов из методичек не копируются дословно: Google ограничивает обычный запрос 32 словами, поэтому избыточные варианты могли бы быть проигнорированы.

**Важное ограничение методичек:** в них отдельно рекомендован поиск через Google Картинки для соцсетей Бангладеш и Малайзии. В текущем мониторе строки запроса открываются в обычной веб-выдаче Google Search; отдельный режим `tbm=isch` и обработчик результатов Google Images не добавлялись. Социальные запросы этих профилей поэтому выполняются как обычный поиск по указанным платформам.

## Версия 1.5.1 — название профиля как единственный регион для фильтра СМИ

При формировании запроса к ChatGPT целевой регион берётся только из поля названия выбранного профиля (`profile.name`). Код Google `gl` и языковые настройки профиля в запрос больше не передаются. Данные самих результатов поиска (URL, домен, заголовок, сниппет и запросы) по-прежнему передаются для идентификации издателя.
